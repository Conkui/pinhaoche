# 拼好车 V1 产品规格

## 目标与边界

V1 服务于偏僻学校学生的拼车出行，只覆盖“预打车”和“已打上”两条链路。地点只能来自管理员维护的预设地点或单次记录的用户自定义文本；不申请定位、不接地图 SDK、不做附近推荐和模糊匹配。

`Ride` 是唯一拼车聚合：预打车列表展示 `PUBLISHED`、`MATCHING`；已打上列表仅展示 `BOOKED`。`BOOKED` 表示已叫到车但车主仍愿意等人；车主点击“不再等人”后转为 `IN_PROGRESS` 并从列表移除。

## V1 核心旅程

1. 用户 A 选择预设或填写自定义出发地、目的地，发布预打车。
2. 用户 B 在预打车列表看到路线、时间和余位，联系 A；已有会话复用，没有则创建。
3. A 确认同行者并叫车，通过合规的分享文本或 OCR 导入经用户确认的信息，Ride 进入 `BOOKED`。
4. 用户 C 在已打上页看到路线、余位、等待意愿，立即联系车主；离线车主可收到微信订阅消息。
5. C 加入后，A 点击“不再等人”，Ride 转为 `IN_PROGRESS`。

## 业务规则

- 预设地点在 Ride 创建时必须冗余写入 `origin_text`、`destination_text`，作为不可变历史快照。
- 自定义地点只归属当前 Ride，不写入公共地点库。
- 所有写接口要求 `Idempotency-Key`；同一用户、同一动作、同一键只能产生一次有效结果。
- 加入人数必须以带 `version` 和容量条件的单条 SQL 更新为准；受影响行数为 0 时返回容量已满或并发竞争错误。
- 车牌和距离可为空；OCR/分享文本导入的低置信度字段必须由用户确认。没有正式第三方 API 时，距离必须显示更新时间且不得称为实时。
- 聊天消息先在同一事务内落 MySQL，再 ACK 并推送；Redis 不保存聊天事实。

## 非目标

不实现支付、自动派单、地图导航、GPS、第三方私有数据读取、抓包/Hook/模拟登录，也不把 OCR 识别结果在未确认时自动发布。
