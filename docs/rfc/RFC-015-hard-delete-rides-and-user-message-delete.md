# RFC-015：管理员物理删除拼车单与用户消息删除

## 决议

- 管理端的单条与批量“删除”改为物理删除，而非 `admin_ride_suppression` 隐藏。每次批量仍最多 100 个明确勾选的订单 ID。
- 删除一个拼车单必须在同一事务中清理其 `ride_member`、相关 `chat_session`/`chat_message`、对应的 Outbox 事件、订单幂等记录以及旧的隐藏审计记录，再删除 `ride` 本身；任何一步失败必须整体回滚。
- 这是不可恢复的测试数据清理工具，页面必须二次确认并明确提示会清理关联聊天记录。
- 聊天页面允许用户长按**自己已成功发送**的一条消息，在按压位置显示删除按钮；服务端必须验证会话成员与 `sender_id`，禁止删除他人消息。删除后该用户本地列表立即移除，历史拉取不再返回该消息。

## 契约边界

- 不改动冻结的 `openapi.yaml`、`V1__init.sql`、Ride 状态机或 WebSocket V1 协议。
- 新增的消息删除 HTTP 路由及管理员 `bulk-delete` 路由按本 RFC 实现；旧 `bulk-suppress` 路径仅作兼容别名。不推送 WebSocket 撤回事件，因此对方已打开的旧页面会在下一次历史刷新后同步消失。

## 状态

Integration 已接受；独立审查通过，并已补齐并发删除锁、会话外键与消息待确认索引重建。
