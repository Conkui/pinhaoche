# RFC-013：找拼友路线筛选、已打上发布门禁与管理端抑制

## 决议

- “找拼友”页增加出发地、目的地两个独立筛选器：预设地点下拉或用户输入的精确文本；两项同时填写时按 AND 过滤，筛选只作用于已取得且仍符合预打车时效红线的列表。
- 现有 `realtime_carpool_setting.enabled` 延续既有语义：`true` 允许“我已打上车，发布行程”；`false` 时入口与提交均显示管理员公告并拒绝。该门禁覆盖客户端和服务端导入写路径。
- 管理端新增拼车“删除”操作。为不篡改冻结 Ride 状态机或历史事实，采用新的运营抑制记录（含 ride id、管理员操作时间），而不是物理删除 Ride；公开/管理读取需排除被抑制记录，管理员可审计。

## 边界

- 不修改 `V1__init.sql`、Ride 状态机、WebSocket 或既有 Ride DTO；数据库变更通过后续 Flyway 迁移。
- 管理端接口仍沿用 `X-Admin-Key` 保护，新增端点不直接修改冻结 OpenAPI。

## 状态

Integration 已接受，待实现、独立审查和验收。
