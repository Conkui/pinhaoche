# RFC-012：实时拼开关、公告与加入后联系

## 背景

发布者需要在有人加入后立即获知，并能从“我的发布”进入该订单联系同行者；运营人员还需要在不可服务时一键关闭“实时拼”，向用户展示可编辑公告。

## 决议

- 加入成功后，`ride` 模块在**同一业务事务**写入 `RideMemberJoined` Outbox 事件；通知消费者以该事件通知发布者。幂等重放或失败加入不产生第二条事件。
- 仅 Ride owner 查询“我的发布”时返回该 Ride 的同行者最小联系资料（用户 id、昵称、头像）。小程序使用既有的 `POST /chat-sessions` 创建或复用会话；不新增直接联系方式，也不向非 owner 暴露成员资料。
- 新增 V3 Flyway 迁移保存单例运营设置：`realtime_carpool_enabled` 与公告正文。新增受 `X-Admin-Key` 保护的管理端读写接口；该接口不修改小程序冻结 `openapi.yaml`。
- 默认值为 `enabled=true`，本次交付完成后保持开启。关闭时小程序预打车入口切换为公告页，阻止用户继续进入该功能。

## 影响与边界

- 涉及 `ride`、`notification`、`admin/feature` 和小程序预打车/我的发布页面；不改 V1 初始化迁移、状态机、WebSocket 协议与既有 DTO 字段语义。
- 运营开关是服务可用性提示，不能取代后端写操作的权限与状态校验。若需要将开关作为发布/加入的强制后端门禁，必须在后续 RFC 中明确 Ride service 的依赖方向与失败码。
